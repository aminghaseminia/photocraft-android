# PhotoCraft for Android

The Gradle project that packages `apps/photocraft-android`. The Rust half is a `cdylib` built with
`cargo-ndk`; Gradle does not compile any Rust.

This is a **scaffold**, not a store-ready app. It targets a **10" tablet in landscape**; the
manifest locks the orientation because the dock layout is desktop-shaped. See
`docs/android-port.md` for the assessment, the known gaps and the work that remains.

## Layout

| Path | What it is |
| --- | --- |
| `apps/photocraft-android/` | Rust shell: `android_main`, eframe options, `Services` (see below) |
| `crates/android-jni/` | Safe wrapper over the JNI calls (the only `unsafe` in the Android port) |
| `packaging/android/app/src/main/java/.../MainActivity.java` | GameActivity subclass and the JNI methods Rust calls |
| `packaging/android/app/src/main/jniLibs/` | Built `libphotocraft_android.so`, generated by cargo-ndk (git-ignored) |
| `packaging/android/app/src/main/AndroidManifest.xml` | No permissions, fullscreen theme, lib name, landscape lock |

How the two halves talk:

- `MainActivity` is a `GameActivity`; `android-activity` loads the cdylib and calls `android_main`.
- Rust calls the activity's `photocraft*` methods over JNI. The activity instance comes from
  `ndk-context`, so no `FindClass` on a native thread is needed.
- Pickers are asynchronous. Java stores the result, and Rust polls it once per frame through
  `Services::os_events` (`apps/photocraft-android/src/bridge.rs` + `services.rs`). That is also how
  the back gesture reaches the app.
- Files are content URIs: opened documents are read into memory (`FileDialogAnswer::Contents`) and
  saved back with `openOutputStream`. There is no path-based file access; scoped storage forbids it.

## Prerequisites

- Rust with the Android targets:

  ```sh
  rustup target add aarch64-linux-android
  ```

- JDK 17 or newer (`java -version`).
- Android SDK with platform 35, build-tools 35, and an NDK. `sdkmanager` from the command-line tools:

  ```sh
  sdkmanager --sdk_root="$ANDROID_HOME" --install \
    "platform-tools" "build-tools;35.0.0" "platforms;android-35" "ndk;27.2.12479018"
  ```

- `cargo-ndk`: `cargo install cargo-ndk`.
- Gradle (only to generate the wrapper once): `brew install gradle`.

Environment:

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"
```

## Build

From `packaging/android`:

```sh
# 1. Generate the wrapper once (gradle-wrapper.jar is not committed).
gradle wrapper --gradle-version 8.9

# 2. Build the Rust library into app/src/main/jniLibs/<abi>/.
cargo ndk -t arm64-v8a -o app/src/main/jniLibs \
  build --manifest-path ../../apps/photocraft-android/Cargo.toml          # debug
# add --release for a release build

# 3. Package.
./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug         # to the connected phone
adb shell am start -n ai.storyteller.photocraft/.MainActivity
```

The first `cargo build` rewrites `Cargo.lock` for the new package; run it without `--locked`. Commit
the updated lock file. After that, `--locked` works again (including CI).

### 16 KB page sizes

Google Play requires native libraries to support 16 KB pages. NDK r28+ and recent Rust do this by
default. If you build with an older linker, add:

```sh
RUSTFLAGS="-C link-arg=-Wl,-z,max-page-size=16384" cargo ndk ... build --release
```

and check with `zipalign -c -P 16 -v 4 app-release.apk`.

### Release signing

`app/build.gradle` leaves `release` unsigned. Add a `signingConfigs.release` block (ideally reading
`keystore.properties`, which is git-ignored) and `./gradlew bundleRelease` for an `.aab`.

## Debugging

```sh
adb logcat photocraft:V *:S          # the app's own log lines
adb logcat | grep -i -E "wgpu|winit|photocraft"
```

`android_main` runs on a native thread; `android-activity` redirects stdout/stderr to logcat, and
`android_logger` sends `log` records there.

Common failures:

- **Black screen**: look for a `wgpu` adapter error. Vulkan is required; the app falls back to the
  CPU compositor only if a window is created at all.
- **`UnsatisfiedLinkError`**: the `.so` name must be `libphotocraft_android.so` (Rust `[lib] name`),
  `android.app.lib_name` must be `photocraft_android`, and the ABI must be in `abiFilters`.
- **Picker returns nothing**: check that `pendingResult` is drained; the app polls it every frame.

## Not implemented yet

Image clipboard, folder pickers, printing, update checks, display profiles, safe-area/IME insets,
palm rejection, flushing autosaves on `onPause`, and a touch-first layout for phones. Tablet
landscape is the target size; see `docs/android-port.md`.
